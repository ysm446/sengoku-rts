# Prototype 01の接触戦闘・士気・撤退

作成日時: 2026-09-05 11:27
更新日時: 2026-09-05 22:16

## 目的と操作

500対500の2部隊が進軍し、接触戦闘で兵力・隊列・士気を失い、片方が撤退する最小デモ。史実の戦闘力や損害率を再現する数値ではない。Simulationは表示人数を参照しない。

Spaceで開始・一時停止、Homeで初期化。左クリックで選択、右クリックで移動先を変更、Hで停止する。交戦中のHは移動のみを止め、損害を無効にはしない。崩壊前なら移動で離脱できる。撤退中・敗走済みの部隊はMove / Holdを受け付けない。

タイトルバーに進行状態、勝敗、両部隊の状態・残存兵力・士気・隊列・敗走小組数を表示する。部隊状態は待機 → 進軍 → 交戦 → 撤退中 → 敗走済み。勝った側はその場で停止する。

## 更新と接触判定

- 1/60秒の固定刻み。渡された時間の端数は保持し、描画fpsと切り離す。一時停止中は時間を蓄積しない。入力時間は有限の0〜3600秒を受け付ける。
- 初期中心は(0, -22)と(0, 22)、目的地は双方(0, 0)、速度は毎秒1.8。
- 部隊の接触領域は向きに依存しない半幅14の正方形。X/Z両軸で接したら交戦し、小さい重なりの軸へ両部隊を押し戻す。境界では中心が±60を超えないよう補正する。
- 隊列は回転せず、兵士の向きだけ敵へ向ける。正面接敵時は左右端の後方2小組が外側から前進する簡易経路を使う。小組同士の通行判定はあるが、経路探索・障害物回避・多部隊の衝突解決は未実装。小組の現在の向きに対する側面・背後の攻撃補正を使う。

## 戦闘の仮ルール

双方の初期兵力500、隊列100。初期士気は赤100・青85とし、崩壊の差を観察する。陣営名による戦闘補正はなく、士気を逆にすると勝者も逆転する。同条件なら同時に崩壊する。

各固定刻みで双方の位置・敵選択・旋回を確定してから損害を同時適用する。射程7.5以内かつ正面±60度以内で、攻撃線が他の小組に遮られない場合だけ攻撃する。相手から見た正面は1倍・側面1.25倍・背後1.5倍。[接近とコリジョン](local_combat.md)を参照。

```text
小組の攻撃係数 = (小組兵力 / 20) × (0.5 + 備の隊列 / 200) × (0.5 + 小組士気 / 200)
損害候補 = 1.2 × 攻撃小組の攻撃係数 × 方角補正 × 経過秒
受ける損害 = 自分を選んだ射程・向き・遮蔽条件を満たす敵小組の損害候補の合計（兵力上限まで）
隊列の低下 = 被害のある刻みで 1.5 × 経過秒 + 受ける損害 × 0.08
小組士気の低下 = 小組の被害 × 2 + 被害のある刻みの秒 × 0.5 + 近隣の動揺源数 × 6 × 経過秒
備の士気 = 小組士気の合計 / 25（敗走小組は0として集計）
```

兵力・隊列・士気の下限は0。小組の士気20以下または兵力25%以下で局所敗走し、現在位置から半径8以内の同じ備の非敗走小組へ、最大8秒間の動揺を与える。13/25小組が敗走すると備全体が崩壊し、残存小組へ撤退を命じる。備士気・隊列・総兵力だけでは全体撤退を起こさない。備は敵と反対方向へ通常の1.5倍速で退き、撤退先は中心座標±60に制限する。到着で敗走済みとなる。先に敗走した小組の世界座標と退路は備の移動から独立する。

崩壊時に勝敗を確定し、以後の戦闘損害は停止する。同時崩壊は双方敗走。追撃・士気回復・再集結・手動のRetreat命令は未実装。

単独の敗走による動揺は最大48であり、士気100の健全な近隣は耐えられる。複数の敗走が重なる場合や既に低士気の場合は連鎖しうる。刻み開始時の敗走状態から同時に波及を計算し、更新順で連鎖速度が変わらないようにする。[局所敗走の詳細](organization.md)を参照。

## 描画と制限

表示用IDへの損害割当数を小組ごとの残存兵力割合から求め、近くの敵兵と接する生存前列のうち、敵の槍突きが最大伸長コマを通過した攻撃相手だけを死亡表示へ移行する。対象不足時は後列や別の小組へ死亡を流さないため、部隊損害と表示上の死亡数には差が残る。倒れた姿は死亡位置に残す。[個体表示の設計](individual_soldiers.md)を参照。

隊列低下に応じた位置の乱れ、個体ごとの追従と動作時計、前列の槍突きと後列の補充を表示する。兵士は引き続き地形へ接地する。攻撃は専用Spriteを使用する。死亡専用Sprite・画面内HUDは未実装。仮の効果音は実装済み（[音の設計](audio_assets.md)）。倒れる動作は仮表現で、死亡表示は槍突きの命中タイミングに連動するが、部隊損害の計算は個々の命中から独立している。旗と陣幕は初期位置に残す。表示人数を増やしても接触領域や戦闘の結果は変わらない。

## 検証

- Debug / Releaseのビルドと各8件のCTestが成功。
- 戦闘による各値の減少、一時停止、移動離脱、H中の被害、撤退完了、撤退後の命令無効化、初期化、地形端での接触を検証。
- 30fps相当・144fps相当・80秒一括更新で状態が一致。同条件の双方敗走、士気の入れ替えによる勝者の逆転も確認。
- 1,000 / 5,000 / 10,000の表示上限に対する欠員と初期化を確認。
- `dx12_combat`は0.1秒刻みで個体表示を更新し、80枚の描画で80秒を進め、交戦中・局所敗走発生後・終了時の画像を保存する。Releaseの10,000体・WARPでも成功し、DX12警告・エラーは0件。
- 交戦中の欠員と、敗走後に両軍が離れた描画を目視した。実操作での長時間検証と、戦闘の見やすさ・バランスの調整は今後の作業。

小組への配分は[編成の兵力・士気](organization.md)を参照。接敵小組の全滅後は後列へ被害を流さない。小組側の兵力・士気によって両翼と正面両端の交代候補を絞る。敗走した小組は戦闘と交代から除外する。
