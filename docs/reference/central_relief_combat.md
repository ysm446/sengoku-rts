# 中央交代の攻撃有効条件での測定

作成日時: 2026-09-07 00:44
更新日時: 2026-09-07 00:44

## 条件と再現手順

中央交代の経路検証とは別に、敵の攻撃参加を解除せず、最初の交代予約を最大40秒追跡する。両軸・両方向・両陣営・中央三列の24条件に、空き通路の有無と敵の停止命令の有無を掛けた96条件。両軍の士気は100、対象前衛の疲労は9・兵力は19、備の中心間距離は28。空き通路は隣列の前衛・予備を兵力0・敗走済みにして作る。停止命令は敵の接近移動を止めるが、攻撃は有効。通常起動から自然に交代条件へ至る試験ではない。

`tests/central_relief_tests.cpp` の `fixture` を共有し、`--combat-report` 指定時だけCSVを出力する。CTestの経路・停止・初期化テストとは独立した測定モードであり、成功件数を合格条件にしない。

```powershell
$testPath = './build/Release/central_relief_tests.exe'
$reportPath = './build/central-relief-combat.csv'
& $testPath --combat-report | Set-Content -Encoding UTF8 $reportPath
```

Releaseビルド後に実行する。[今回の全96行の結果](central_relief_combat.csv)を保存した。乱数による反復ではなく、固定条件の組み合わせの件数である。一般的な勝率や実戦全体の成功率とは区別する。

## 結果

| 通路 | 敵の移動 | 交代・復帰完了 | 交代後に復帰中断 | 交代前に中断 | 備の平均損失 |
| --- | --- | ---: | ---: | ---: | ---: |
| 空き | 停止 | 24 | 0 | 0 | 31.39 |
| 空き | 接近有効 | 6 | 0 | 18 | 50.73 |
| 密集 | 停止 | 0 | 21 | 3 | 55.99 |
| 密集 | 接近有効 | 0 | 0 | 24 | 76.15 |

密集時の通路準備は全48条件で完了し、開始から約4.53秒を要した。その後の交代前中断45件のうち42件で予備が敗走、3件で元の前衛が敗走した。敵停止時の密集21件は配置枠を交換できたが、列の復帰まで完了しなかった。そのうち5件では交代した予備が敗走、16件は前衛・予備がともに非敗走のまま復帰予約が解除された。後者の接敵解除・方向変更の内訳はまだ計測していない。

備の損失は測定開始時から予約解除または観測終了までの兵力差。空き通路の初期欠員は含めない。終了時間が条件によって異なり、交代を無効にした対照群もないため、交代機能が追加した損失量とは解釈しない。

CSVの時刻はシミュレーション開始からの秒で、未到達は-1。`restored` は枠交換後に予約を解除し、通路を作った全小組が非敗走・標準位置・通常待機へ戻った状態。空き通路では復帰対象がない。`exchanged_interrupted` は枠交換済みだがその復帰条件を満たさず予約解除、`aborted` は枠交換前の予約解除。`pending` は観測終了時に予約継続、`not_started` は予約なし。`last_phase` は最後の更新直前の段階（0〜3が交代、4が準備、5が復帰）。

## 次に確認すること

予備の前進中の被害と敵の進入による滞留、復帰中の接敵解除・方向変更を個別に追跡する。その上で経路と予約の継続条件を調整する。今回、攻撃力・士気・移動速度などの本体の数値は変更していない。実画面と手動操作の確認は未実施。

通常起動の初期士気は赤100・青85で、撤退差を観察する試作条件。赤勝利を固定する処理はなく、敗走と消耗の継続から勝敗を決める。今回の測定では士気を揃えてこの初期差を除いている。
