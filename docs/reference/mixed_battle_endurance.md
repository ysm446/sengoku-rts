# 混成戦の長時間測定

作成日時: 2026-09-07 04:26
更新日時: 2026-09-07 05:00

疲労・休息の追加後、実際の混成戦で交代と再投入が発生するかを測定した。戦闘本体はd634c9cのまま。測定用の実行ファイルとCSVを追加し、戦闘の数値や行動条件は変更していない。

## 条件と再現

60Hzの固定更新で最大180秒、勝敗が決まれば終了する。描画・手動命令なし、攻撃・士気・敗走・自律移動は有効。各条件でFormation全体を陣営間で交換した対照試行も実行する。所属する兵種、士気、位置、向き、命令先をまとめて交換し、陣営の色だけで結果が変わらないかを確認する。

| configuration | 条件 |
| --- | --- |
| 0 | F8標準。赤士気100・青85、中心X=-6/+6。既存の異なる兵種配置を維持 |
| 1 | F8の位置と兵種を維持し、両軍士気100 |
| 2 | 両軍士気100、中心X=0で左右差なし。兵種配置の差は維持 |

乱数による勝率測定ではなく、3つの決定的な条件と交換対照の計6戦。部隊編成まで等しい対戦ではない。

```powershell
$reportPath = 'docs/reference/mixed_battle_endurance.csv'
$runnerPath = 'build/Release/mixed_battle_tests.exe'
& $runnerPath --report | Set-Content -Encoding UTF8 $reportPath
```

`tools/build.ps1 -Configuration Release -Test`でビルドできる。引数なしのCTest `mixed_battle_endurance`は標準配置と陣営交換を30秒ずつ実行し、兵力が増えないこと、編成の兵力合計、疲労の範囲、陣営交換時の結果・行動指標の一致を検証する。休息件数や特定陣営の勝利は合格条件にしない。180秒測定は`--report`で明示的に実行する。

## 交代が始まらない理由と次の対応

消耗条件（疲労8以上・兵力75%以下・士気50以下のいずれか）を満たす最前列スロットの生存・非休息小組について、標準位置からの変位を計測した。その累計時間の約73%（標準）、64%（士気100）、100%（左右差なし）で接近変位または経路変位が残っていた。

現在の交代開始条件は、前衛・予備の接近変位がともに0で、前衛の経路変位も0であることを要求する。接敵移動した小組はこの条件で除外される。これが実戦で交代を使えない障害の一つと判断する。変位のない残りの時間にも交代が始まらない理由は、予備の状態・通路予約・占有条件を追加調査する必要がある。

次は標準位置から離れた前衛の実位置を起点に交代経路を組み、退路・予備の前進経路を両方確認する。休息の係数だけを上げても、休息に入らない問題は解消しない。左右差なしの停滞については、健全な予備の接近制限と帰還・交代予約も調査する。

## 指標の定義

- `team`と`winner`は0=赤、1=青。`winner=-1`は勝者なし。`swapped=1`は陣営交換後。
- `exchanges`は配置スロットが変わった小組数を2で割った回数。交代通路の復帰完了とは別。
- `rest_completed`は休息フラグが解除され、非敗走・士気70以上・疲労2以下になった回数。`reused`はその後に再び攻撃可能になった回数。
- `disengaged`と`regrouped`は騎馬の状態遷移回数。`charges`は実際の突撃命中回数。
- `*_group_seconds`は小組ごとの時間の合計で、壁時計の時間ではない。25小組が1秒待つと25小組秒。
- `fatigue_recovered`は疲労減少量の合計。`mean_attack_efficiency`は攻撃可能だった各固定更新の表示効率の時間平均で、損害で重み付けした平均ではない。
- 交代中断数は交換前の予約解除を数える。前衛・予備の敗走数は同じ中断に重複して含まれる場合がある。

Release全30テスト成功（約54秒）、追加した混成長時間テストはDebugでも成功（約11秒）。最大180秒の6戦はReleaseで実行した。これらは整合性と再現性の検証で、交代・休息の実戦上の有効性を達成済みとするものではない。手動操作や描画の自然さは今回の測定対象外。
